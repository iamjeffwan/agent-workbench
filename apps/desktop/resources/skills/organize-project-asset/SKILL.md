# Organize Project Asset

Create the complete Markdown content for one project knowledge file.

## Rules

- Treat the user's stated experience as the only proposed lesson. Do not independently invent further rules or recommendations.
- Do not copy or summarize the task flow document. Organize only the experience that the user explicitly entered.
- Preserve useful existing content and its tone, structure, terminology, and level of detail.
- Integrate the lesson where it naturally belongs. Avoid duplicating an existing rule.
- Make applicability explicit when the lesson is useful only for a certain kind of task.
- Prefer concise, actionable wording. Do not turn one incident into a universal rule unless the user explicitly did so.
- Return the complete final Markdown document, not a patch, explanation, JSON object, or fenced code block.
- Do not modify source code, scripts, tests, or any file other than the selected Markdown document.
