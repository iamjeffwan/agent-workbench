# 本地审查数据库开发结果 v0.1

## 1. 本次目标

将审查案例、审查运行、模型判断、证据和人工确认从进程内存迁移到每台设备独立的 `SQLite`（本地嵌入式数据库），并提供无界面的查询、导出、备份和健康检查入口。

本次不包含优化域、桌面界面和云同步。现有 `.review-runs`（审查产物目录）继续保留，但不导入数据库。

## 2. 数据怎样保存

数据库默认位于 `%LOCALAPPDATA%\Agent Workbench\data\agent-workbench.db`（当前设备的工作台数据库文件）。可以通过 `--database`（数据库文件参数）指定完整文件，也可以通过 `--data-dir`（数据目录参数）指定存放目录。

数据库包含六类业务记录：

1. 审查案例；
2. 案例选择的会话和回合；
3. 审查运行；
4. 模型判断；
5. 判断引用的证据；
6. 人工确认。

模型用量和运行产物索引使用 `JSON`（结构化数据）字段保存。完整原始会话、模型请求、模型输出和日志仍保存在文件系统；数据库只保存运行产物的绝对路径、文件大小和内容哈希。密钥和令牌不进入数据库。

## 3. 一致性规则

- 每次案例创建会同时保存所选回合，任一步失败都会整体回滚。
- 审查开始时保存运行中状态；完成或失败时以事务更新运行，并一次性保存判断与证据。
- 模型判断必须属于已完成的审查运行，而且至少包含一条有效证据。
- 人工确认只追加，不覆盖原始模型判断。
- 重复编号、缺失关联和非法状态变化会被数据库与领域校验共同拒绝。
- 数据结构升级通过有编号的迁移执行，同一个迁移不会重复应用。

## 4. 命令行使用

真实观测审查沿用：

`pnpm review:run:observation -- <参数>`（执行真实观测审查）

完成后输出数据库路径、案例编号、运行编号和审查结果。该入口会自动把准确的原始会话文件交给原始记录读取器。

本地验收可以使用：

`pnpm review:acceptance:local -- <参数>`（读取真实观测，但使用本地确定性模型结果，不发送项目内容）

该入口用于在没有模型额度或不希望外发项目内容时，验证数据库写入、重启查询、人工确认、导出和备份流程。

本地记录管理统一使用：

`pnpm review:local -- list`（列出最近的审查案例）

`pnpm review:local -- show --case-id <案例编号>`（查看完整审查记录）

`pnpm review:local -- annotate --judgement-id <判断编号> --verdict correct --reason <确认原因>`（追加人工确认）

`pnpm review:local -- export --case-id <案例编号> --output <文件>`（导出可阅读的数据文件）

`pnpm review:local -- backup --output <数据库备份文件>`（创建一致性备份）

`pnpm review:local -- doctor`（检查数据库完整性和迁移状态）

所有命令都支持 `--database <数据库文件>`（覆盖默认数据库文件）或 `--data-dir <目录>`（覆盖默认数据目录）。

## 6. 当前边界

- 数据库只供当前设备使用，另一台设备不能直接读取。
- 正式跨设备访问仍由后续云同步模块实现。
- 当前不建立优化案例、优化方案、审批或经验版本数据表；这些对象在优化域实现时通过新迁移加入。
- 数据库本身不保存凭据，也不替代原始日志和正式经验的文件版本管理。

## 7. 后续验收操作约定

### 临时目录清理

验收脚本只能清理本轮运行成功创建并登记的路径。运行开始前已经存在的目录，即使名称符合临时目录约定，也不能根据名称推断归属；归属未知时保持原状。需要移除时使用系统回收站，并在操作后确认原路径已经消失。公共实现见 `scripts/local-operation-safety.mjs`（本地操作安全模块）。

### 子进程终止

停止桌面端或验收子进程前，先读取进程名称、父进程和命令行，并与本轮启动时的身份约束比较。身份读取失败、进程已退出或身份不匹配时不执行强制终止，只返回诊断结果。桌面启动器已接入该约束。

### 依赖安装

统一使用 `pnpm install:deps`（依赖安装入口），默认设置非交互环境和 `--frozen-lockfile`（锁文件冻结）模式，不自动重复重试。锁文件过期时明确使用 `pnpm install:deps -- --update-lockfile`；离线环境使用 `--offline`（离线）并要求本地缓存完整。入口支持 `--timeout-ms`（超时毫秒数），超时后只结束当前直接子进程的等待并报告原因，不按未知进程编号扩大终止范围。
