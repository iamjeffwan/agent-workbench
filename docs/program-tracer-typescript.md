# TypeScript / Node.js 程序追踪器（首版）

首版只覆盖仓库现有的 TypeScript 与 Node.js。桌面应用继续使用原来确定的技术方案；追踪器本身用 TypeScript 编写，编译为 JavaScript 后在 Node.js 中运行。

## 组成

1. **边界分析器**  
   启动项目前读取源码：找到接口文件中的抽象方法，找到继承它的实现文件及具体方法，生成“需要追踪哪些实现方法”的清单。

2. **节点加载器**  
   桌面应用启动项目进程时，在接缝注入进程来源编号，并通过 `NODE_OPTIONS` 预加载观察模块。加载器只处理清单中的具体方法，在模块进入内存、尚未执行时临时加入记录逻辑，不写回源码，也不处理依赖包。预加载模块可进入主线程、工作线程和派生进程。

3. **运行记录器**  
   具体方法执行时：进入方法 → 保存参数和开始时间 → 执行原方法 → 保存返回值或异常 → 保持原结果继续返回。异步调用使用 `AsyncLocalStorage` 保持父子关系。记录经过凭据隐藏后，通过本地进程通信发送给桌面应用。

例如追踪 `fetch` 时，只会得到方法名、参数、返回摘要和耗时，不会记录它内部的循环、局部变量和第三方解析函数。

## 注入与转换

- 观察模块注册同步加载钩子，只处理项目目录内、且出现在清单中的代码。
- 代码载入内存时做 AST 转换，自动加入函数进入、返回、抛错记录；同步钩子比跨线程异步钩子更适合控制开销。
- 转换结果按文件内容散列缓存，源码映射和函数编号只生成一次。

## 性能与完整性

- 不采样函数调用。采样只能提供近似热点，无法满足“清单内全部调用”；调试器逐调用暂停则开销过大。
- 高频路径只写整数编号、时间和父调用编号，进入内存环形缓冲区后批量发送，禁止每次调用同步写盘。
- 值快照设置深度、数量、字节和耗时上限；普通值保存内容，复杂对象转为摘要。
- 缓冲区压力过大时先降低值快照精度。若仍超限，只能选择阻塞程序以保全记录，或明确标记“记录不完整”；不能静默丢失。

## 编号

- 进程来源编号：启动时由环境传入，说明哪个工具启动了进程。
- 当前活动编号：长期进程处理后续请求或任务时另行建立并传播；见 `adr/0016`。
