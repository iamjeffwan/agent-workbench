# `HTTP Toolkit UI`（界面项目）近期组件审计

## 审计目的

这次只研究代理工作台近期界面会用到的部分，判断哪些能力来自公开依赖，哪些是上游项目自己编写的代码。审计结果用于下一步迁移到 `React`（界面框架），本轮不修改桌面界面，也不安装新依赖。

这里的许可证判断用于工程选型，不替代正式法律意见。

本地副本整体由 `.research/`（研究目录）规则排除，不会进入工作台版本历史。后续更新上游前，应先重新记录提交编号并复核本文件。

## 结论

近期界面不能直接搬用上游页面组件。应用外壳、侧栏、筛选、活动列表行、详情卡片和折叠状态都是上游自研代码，并且普遍依赖它的网络事件模型、账户状态和 `MobX`（状态管理库）。这些文件即使经过删减和改名，仍然来自上游实现。

可以直接采用的是它依赖的独立公开组件库。工作台应从这些库的官方包重新安装和调用，不经过上游封装层：

- 图标直接使用 `@phosphor-icons/react`（图标组件库）。
- 分栏直接使用新版 `react-split-pane`（可调整分栏组件），不复制上游包装组件。
- 活动量较大时直接使用新版 `react-window`（虚拟列表组件），不复制上游列表实现。
- 字体可以直接使用 `DM Sans`（界面字体）与 `DM Mono`（等宽字体）的官方字体包。

其余界面按工作台的数据结构重新组合。这里的“重新组合”允许阅读上游源码确认行为，但页面结构、状态接口和实现代码由工作台自行编写。

## 与现有界面规格的对应关系

### 应用外壳规格

- 三栏布局：重新实现应用外壳，并直接使用新版分栏公共组件。
- 左侧导航：重新实现导航状态，只直接使用公共图标。
- 项目抽屉：属于工作台自有功能，不从上游寻找对应源码。
- 字体与配色：字体可直接采用公开字体包，颜色和间距继续由工作台维护。

### 活动表格规格

- 固定表头、状态标记、来源、类型、名称和耗时：全部按工作台执行步骤模型实现。
- 行选择与详情联动：由工作台管理选中编号，不采用上游网络事件选择逻辑。
- 探查组展开：用工作台树形数据和局部折叠状态实现。
- 搜索与来源筛选：保留现有语法，不采用上游筛选解析和建议生成代码。
- 大数据量：只复用新版虚拟列表公共组件。

### 详情检查器规格

- 摘要卡片、关键字段、参数、输出和原始数据：重新编写工作台卡片。
- 折叠状态：使用标准可访问属性和工作台局部状态。
- 复制操作：重新实现剪贴板反馈，不采用上游复制按钮代码。
- 空状态与关闭动作：使用工作台自己的选择状态和文案。

三份规格中的界面部分均已有处理结论，没有需要直接复制的上游自研组件。

## 明确不采用的部分

- 不复制 `src/components`（上游组件目录）中的任何文件、样式片段或状态逻辑。
- 不采用 `MobX`（状态管理库）；现有桌面数据接口足以支持首批界面。
- 不采用 `styled-components`（组件样式库）；继续使用工作台自己的样式层，避免把上游主题结构带入。
- 不采用 `react-autosuggest`（自动建议库）；该项目长期缺少维护，而且工作台当前筛选语法较小。
- 不采用上游旧版分栏包装和旧版自动测量组合。
- 不采用上游标志、浏览器品牌图标、自有图片、产品名称和文案。
- 不采用上游网络事件、账户、付费功能、规则编辑与路由模型。
