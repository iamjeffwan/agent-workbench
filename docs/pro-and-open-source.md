# 后续版本：Pro / 团队与开源收费

本文记录后续付费能力方向，以及开源与收费的切法。首版仍以旁路观察为主；下文是方向约定，不是已实现承诺。

## 分层

| 层 | 做什么 | 产物 |
|----|--------|------|
| 现在（免费观察） | 旁路读取代理与程序记录，组时间线与详情 | 可追溯的执行步骤 |
| Pro / 团队 | 在观察之上沉淀资产，并支撑系统评测与优化 | 错误库、可调用方法、评测与回归闭环 |

工作台仍然不替代 Cursor、Codex 等工具里的对话与需求调整。付费层卖的是观察之后的沉淀与系统工程，不是再做一个代理客户端。

## Pro 能力聚焦

### 1. 错误变成数据资产

代理任务出错时，通过工作台里的若干步骤定位模型或流程问题。错误若只被人记住，只是经验；若经过分类、保存，并接入后续测试与优化，就成为可复用的数据资产。

### 2. 复盘后固化为工具或方法

对复盘结论做筛选：哪些步骤可以封装成工具或固定方法，方便以后的人或 AI 直接调用。

### 3. 面向个人 / 团队的 AI 系统稳态

把「基于 AI 的系统」理解为：

`基础模型 + 上下文 + 数据 + 工具 + 状态 + 验证 + 反馈`

再配上自有标准、数据集和测试优化流程。当模型切换、模型升级、工具升级或状态等参数变化时，用同一套流程把稳定性、效率和能力拉回较好状态。

第 3 条是总目标；前两条是往这个目标输送原料的管线。第一刀更适合从第 1 条（错误资产化）做起，最贴近已有的步骤观察能力。

## 免费 / Pro / 团队怎么切

| 档位 | 大致范围 |
|------|----------|
| 免费 | 本地观察：时间线、步骤、详情、基础筛选 |
| Pro | 错误分类入库、个人复盘库、封装候选、个人侧评测集与回归 |
| 团队 | 共享错误库 / 工具库 / 标准与数据集、权限与协作；完整评测与优化闭环 |

## 定价与规模（粗估）

仅作独立产品情景参考，不是财务预测。

**定价区间（示意）**

- 个人 Pro：约 `$12–25` / 人 / 月（年付可略优惠）
- 团队：约 `$20–40` / 席 / 月
- 偏系统优化的团队包：约 `$200–800` / 队 / 月，或按席上浮

**可能的健康一期**

- 付费席位：大约数百席量级
- 月经常性收入：大约数千到一万多美金
- 年经常性收入：大约数万到十几万美金量级时，较接近「可全职维护」的独立产品形态

转化会偏低（观察免费、付费偏工程资产）。个人订阅堆量有限；若团队真为「换模型仍能稳住」付钱，收入更可能被少数团队客户拉高。

## 开源与收费方案

不采用「免费版开源、付费版整段闭源」作为默认假设；也不必强制「连付费功能源码全部公开」。

更顺的切法：

| 部分 | 倾向 |
|------|------|
| 观察底座（桌面壳、时间线、适配器、本地读取与展示） | 开源 |
| 个人侧错误分类、本地封装草稿等 | 可开源，也可用账号解锁 |
| 云端资产库、团队共享、托管数据集、回归评测服务、权限与审计、一键优化闭环 | 以服务与协作收费；不必依赖整段闭源客户端 |

护城河更宜放在数据资产、工作流与团队网络效应上，而不是只靠藏几段界面代码。

许可证具体选型（MIT / Apache / AGPL 等）另定；本文只约定分层原则。

## 与现有约定的关系

- 桌面端仍是观察壳；首版继续以本地文件观察为主。
- 不承接代理原有的任务管理、反馈打回等开发流程。
- 付费层提供证据、资产沉淀与评测闭环；真正改 prompt、工具或配置，仍由人或现有代理完成。
